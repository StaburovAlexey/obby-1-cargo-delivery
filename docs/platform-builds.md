# Сборки для Яндекс Игр и VK

Общая игра, две отдельные интеграции SDK. Исходники остаются в `dist/`; результаты сборки игнорируются Git. Нужны Node.js 22.23.3 и `npm ci`.

| Команда | Результат |
| --- | --- |
| `npm run build` или `npm run build:yandex` | `build/`, SDK Яндекс Игр |
| `npm run build:vk` | `build-vk/`, официальный VK Bridge |
| `npm run build:all` | Обе папки, последовательно |
| `npm run dev` или `npm run dev:yandex` | Локальный SDK Яндекса, порт 8083, доступ с телефона |
| `npm run dev:vk` | Локальный SDK VK, порт 8084, доступ с телефона |
| `npm run preview` / `npm run preview:vk` | Соответствующая production-сборка |
| `npm run build:demo` / `npm run build:vk:demo` | `build-demo/` / `build-vk-demo/`, явно тестовый SDK |

Каждая сборка очищает только собственную выходную папку. В VK-сборку включены иконки пяти покупок и лицензия VK Bridge. Обычный `npm start` по-прежнему открывает исходную локальную версию Яндекса.

## Онлайн и размещение

`npm run server` запускает общий сервер комнат на 8082. Оба dev-сервера проксируют `/ws` к нему. Для релиза задайте один и тот же `PUBLIC_MULTIPLAYER_URL=wss://YOUR_DOMAIN/ws` для обеих сборок; добавьте фактические origins обеих страниц игры в `ALLOWED_ORIGINS` серверного процесса. Это origins iframe, а не адреса страниц каталога. При отсутствии URL production-игра остаётся одиночной.

Для VK дополнительно задайте `PUBLIC_VK_API_URL=https://YOUR_API_DOMAIN` — origin платёжного API, без `/api/vk`, query или секретов. На собственном хостинге игры и API можно оставить переменную пустой: запросы идут на `/api/vk/` того же origin. При размещении статики на хостинге VK нужен абсолютный адрес API. Изменения публичных переменных требуют пересборки.

Пример двух релизных сборок:

```sh
PUBLIC_MULTIPLAYER_URL=wss://online.example.com/ws PUBLIC_VK_API_URL=https://api.example.com npm run build:all
```

На соответствующий хостинг передаётся содержимое `build/` или `build-vk/` с `index.html` в корне. Поддерживаются относительные пути к ресурсам. Сервер комнат общий, а аккаунты, сохранения и покупки Яндекса и VK независимы. Для Яндекса сохраняется прежняя инструкция [yandex-online.md](yandex-online.md).

## Прогресс и реклама VK

VK инициализируется через `VKWebAppInit`. Прогресс и настройки используют VK Storage с отдельным ключом `urbanRouteSave_vk`; локальные данные Яндекса не импортируются. При ошибке начального чтения игра предлагает повторить загрузку. Неподтверждённые записи отмечаются как несохранённые и повторяются по общей политике облака. Перед записью проверяется ограничение в 4096 UTF-8 байт; слишком большое сохранение не обрезается. Новые поля карьеры нужно проверять также на максимальный размер.

Реклама использует interstitial через `VKWebAppCheckNativeAds` / `VKWebAppShowNativeAds`. Если клиент не поддерживает метод или рекламы нет, игра продолжает работу. Сохраняются действующие таймер, предупреждение и проверка безопасного места. Скрытие/возврат приложения используют `VKWebAppViewHide` / `VKWebAppViewRestore`; пауза платформы независима от рекламной и платёжной пауз.

Локальные dev/demo SDK хранят данные только в памяти и не выполняют настоящие рекламные или платёжные вызовы. Production-сборка VK требует запуска внутри VK и не переходит в локальный режим при ошибке SDK.

## Постоянные покупки VK

Пять ID совпадают с Яндексом: `skin_dancing-npc-girl`, `skin_jandel`, `skin_kreekcraft`, `skin_spyder-sammy`, `skin_spider-man`. Это независимые покупки каждой платформы. VK-цены выражаются в голосах и задаются отдельно: значение 39 из Яндекса не переносится.

Серверный каталог — `server/vk-products.json`. Укажите положительную целую `price` для каждого товара либо задайте общую цену `VK_SKIN_PRICE_VOTES`. Пустая переменная сохраняет индивидуальные цены каталога; товар без цены останавливает запуск сервиса. Иконки доступны в VK-сборке по `assets/inapp/skin_*.png`; `VK_GAME_URL` должен указывать на публичную HTTPS-папку этой сборки.

1. Скопируйте `deployment/obby-vk.env.example` в игнорируемый `deployment/obby-vk.env` и заполните ID приложения, секрет, URL игры, цену, точные разрешённые origins и путь базы. Для локального сервиса выберите `VK_DATABASE_PATH=./data/vk-purchases.sqlite`.
2. Запустите `node --env-file=deployment/obby-vk.env server/vk-server.mjs`. По умолчанию он слушает только `127.0.0.1:8085`; `/health` показывает готовность. `npm run server:vk` использует уже переданные переменные окружения. Dev-сервер VK проксирует `/api/vk` на 8085.
3. Подключите HTTPS-прокси по примеру `deployment/nginx-vk.conf`. В кабинете приложения укажите callback `https://YOUR_API_DOMAIN/api/vk/payments/callback`.
4. Оставьте базу на постоянном диске. Сервис использует встроенный `node:sqlite` (в Node 22 ещё experimental), WAL и транзакции; запускается одним экземпляром. Для systemd предусмотрены `deployment/obby-vk.service` и `/var/lib/obby-vk`; сервис использует существующего пользователя `obby-online`. В шаблоне `ExecStart` ожидает Node 22.23.3 по `/usr/bin/node`: при другом расположении задайте полный путь к бинарнику, поскольку systemd не загружает профиль NVM. Для Docker есть отдельные `Dockerfile.vk` и `compose.vk.yaml` с постоянным томом. Примеры сами ничего не устанавливают.

Бэкенд проверяет MD5-подпись платёжных уведомлений VK и HMAC-подпись параметров запуска для чтения покупок. Секрет не попадает в клиентскую сборку. Подписанные параметры запуска передаются в заголовке Authorization; не добавляйте этот заголовок в access-логи. Параметры старше 24 часов отклоняются: нужно заново открыть игру в VK.

`GET /api/vk/catalog` возвращает товары; `GET /api/vk/purchases` — подтверждённые права пользователя. `POST /api/vk/payments/callback` принимает form-urlencoded `get_item` и `order_status_change`, включая варианты `_test`. Скин выдаётся после транзакционной записи `chargeable`. Дубли возвращают прежний номер заказа; смена пользователя/товара в существующем заказе отклоняется. `refunded` убирает право, а поздний повтор `chargeable` не восстанавливает возвращённый заказ. Перезапуск процесса не теряет покупки.

Ответ окна `VKWebAppShowOrderBox` сам по себе не выдаёт скин. После успеха клиент проверяет сервер до 30 секунд. Если уведомление задержалось, право восстанавливается при входе в магазин, возвращении фокуса/приложения, сети или новом запуске игры. Перед новым заказом клиент проверяет существующее право; в текущем сеансе повторное нажатие для ожидающего заказа продолжает проверку без второго платёжного окна. Успешное обновление прав также снимает возвращённые покупки: выбранный скин заменяется на базовый, обычные скины сохраняются. При временной ошибке сервера уже подтверждённые в этом сеансе права сохраняются до следующего успешного ответа.

### Тестовые платежи и резервирование

Добавьте тестировщиков в кабинете VK и перечислите их ID в `VK_TEST_USER_IDS`. Тестовые callback для остальных пользователей отклоняются. Для проверки выдачи тестовых скинов запустите отдельный тестовый экземпляр с `VK_PAYMENT_MODE=test`; такой API отдаёт только тестовые права и только указанным тестировщикам. Production использует `VK_PAYMENT_MODE=live`. Заказы с совпадающими VK order ID в разных режимах разделены; тестовый платёж не создаёт настоящего владения.

Резервируйте базу штатным SQLite backup API или после штатной остановки сервиса. Копия одного файла активной WAL-базы не заменяет согласованную резервную копию. Удаление Docker-тома удалит историю покупок.

## Проверки перед публикацией

`npm run test:platforms`, `npm run test:online`, `npm run build:all`. Эти проверки не выполняют реальные платежи. Внутри тестового приложения VK отдельно проверьте WebGL 2 на телефонах, сохранения между устройствами, правильную цену и валюту, тестовую покупку/отмену/восстановление, задержанный callback, рекламу/её отсутствие, звук и возврат приложения. Проверьте двух клиентов разных платформ в общей комнате.

Результат локального браузера или demo SDK не означает прохождение модерации и не подтверждает реальные выплаты. Официальные материалы: [VK Games](https://dev.vk.com/ru/games/overview), [VK Bridge](https://github.com/VKCOM/vk-bridge), [пример покупок VK](https://github.com/VKCOM/vk-direct-games-example#внутриигровые-покупки).
