# Каньон: дрифт на BMW

Съезд виден у начала основной дороги всем игрокам. В обычном режиме шлагбаум открывается после сохранённого завершения полного основного маршрута. Для въезда нужна наградная BMW.

## Режим разработчика

При явном `?dev=1` в локальной игре без платформенного сервиса или в development-сборке сразу доступны все 11 машин, включая наградную BMW, и въезд в каньон. Покупки и предварительное прохождение не нужны. Машины можно выбрать в ангаре, вернуться и выбрать другую; доступ сохраняется после пересборки сцены. Производственная платформенная сборка игнорирует этот параметр и сохраняет обычные ограничения.

Доступ действует только в текущем режиме: список реально купленных машин и доказательство завершения маршрута не подменяются, карьерные сохранения не записываются. Предпросмотр ещё не полученной машины не создаёт грузовой рейс, не выдаёт деньги, мозги или доказательство прохождения. Все попытки дрифта в режиме разработчика тренировочные: очки считаются локально, рейтинговая попытка на сервере не создаётся и результат в таблицу Яндекса не отправляется. После открытия обычной версии остаётся исходная карьера.

## Этап и управление

Спуск длиной 1 850 м имеет перепад 115 м. Очки начисляются за продвижение в управляемом заносе; комбо растёт на связках. Удар, разворот и обратный ход сбрасывают множитель. Повтор участка не даёт новых очков. Настройки BMW одинаковы для всех попыток. Доставки и заработок мозгов во время попытки не выполняются.

Управление BMW: W/↑/Space — газ, A/D/←/→ — руль, S/↓ — тормоз, Shift — ручник. На экране есть отдельные кнопки. Камера учитывает направление движения. Дым и следы включаются от скольжения; буферы ограничены и очищаются при переходах.

## Таблица Яндекс Игр

В [кабинете игры 631371](https://games.yandex.ru/console/application/631371#leaderboards) 17 октября 2026 создана и проверена таблица:

| Поле | Значение |
|---|---|
| Техническое имя | `canyonDriftV1` |
| Название RU | Каньон: дрифт |
| Название EN | Canyon Drift |
| Тип | Число |
| Сортировка | По убыванию |
| Десятичные знаки | 0 |

Используются актуальные `ysdk.leaderboards.getEntries`, `getPlayerEntry`, `setScore` и `ysdk.isAvailableMethod`. Объект через устаревший `getLeaderboards()` не создаётся. Гости могут смотреть таблицу и сохранять личный рекорд; вход через `ysdk.auth.openAuthDialog()` вызывается только кнопкой игрока. При смене аккаунта незавершённые ответы отбрасываются. Чтение кешируется на 30 секунд, отправки последовательны с интервалом не менее 1,1 секунды; более слабый результат не заменяет сильный.

Документация SDK: https://yandex.ru/dev/games/doc/ru/sdk/sdk-leaderboard и https://yandex.ru/dev/games/doc/ru/sdk/sdk-player.

Для рейтинговой попытки нужен обновлённый сервер комнаты. Он наблюдает движение BMW и сам вычисляет результат с проверкой маршрута, высоты, времени и пропущенных участков. Клиент не передаёт серверу готовое число очков. Затем подтверждённый результат отправляется через SDK Яндекса. Это проверка допустимости наблюдаемой траектории, а не криптографическая защита клиента: SDK и обычные облачные сохранения остаются клиентскими API. Прямые сторонние вызовы SDK требуют отдельной защиты на стороне платформы.

Комната и её ID сохраняются при въезде/выезде. Каньон занимает отдельную область координат общей карты. Ближайшие участники этой же комнаты видны через существующие интерполированные модели; отдельный поиск комнаты не выполняется. Машины других участников сохраняют прежнее поведение отображения без физических столкновений.

В VK и локальной разработке работают сам этап и личный рекорд; рейтинг Яндекса доступен в сборке для Яндекс Игр с действующим SDK. Отсутствие таблицы в кабинете, отказ авторизации и ошибка сети не блокируют повтор заезда.

## Проверка развилки и dev-доступа

Новая развилка использует одну кривую для дорожного полотна, границ столкновений и свободного места между зданиями. Она начинается вдоль главной дороги и плавно поворачивает к каньону. Проверены 52 теста каньона, включая физический проезд BMW по развилке при 30/60/120 FPS без столкновений. Дополнительно проверены все 11 автомобилей в свежем dev-сеансе, повторный вход/выход/пересборка, отсутствие сохранения dev-прогресса и производственные ограничения. Браузерная визуальная проверка этой правки не выполнялась.

## Историческая проверка первоначального этапа

Проверены `npm run test:canyon` (44 проверки), физические проезды при 60/30/15 кадрах в секунду с подтверждением серверным проверяющим, возврат/повтор/пересборка сцены и запоздавшие ответы попытки или аккаунта. Платформы: 59/59; онлайн: 84/84; базовая прогрессия: 29/29 плюс трекер маршрута и режим разработчика BMW. Обе производственные сборки `npm run build:all` собраны успешно; стили каньона входят в сборку.

Два настоящих браузерных клиента подключились к одной комнате, оба загрузили видимую BMW соседа на трассе. ID комнаты сохранялся после въезда и возврата в ангар. Проверены размеры 390×844 и 844×390, отсутствие перекрытия HUD/кнопок, фактические дым и следы без ошибок шейдеров. Для этой проверки в браузер загружалось сохранение из тестового полного прохождения; реальный личный прогресс пользователя не использовался. Headless-браузер рисовал через программный WebGL; проверка не заменяет проезд на физическом телефоне.

Создание таблицы в кабинете игры 631371 подтверждено сохранённой формой `canyonDriftV1`: RU/EN, numeric, по убыванию, 0 знаков. Интеграция проверена через SDK-границу с mock SDK; публикация новой сборки, обновление сервера комнаты и реальная запись игрового рекорда в Яндексе остаются действиями выпуска. Тестовые очки в живую таблицу не отправлялись. Без обновлённого сервера комнаты попытка остаётся тренировочной.

Полный исторический `npm test` снова остановился в `tests/physics-app-integration.mjs`: 6/11, те же пять исходных падений, перечисленных в [отчёте прогрессии](./biome-progression.md#проверка-кода-и-ограничения-общего-набора-тестов). Последующие команды этой цепочки не выполнялись. Отдельно прошли обычная физика (21 проверка), колесо/педали (21), камера/мультитач (27) и численная регрессия десяти обычных машин в `tests/reward-driving.mjs`.

Финальное ревью выявило две существенные ошибки, воспроизведённые отдельными тестами до исправления: отправка предыдущего результата после повтора и потеря ссылки на машину при восстановлении страницы из back/forward cache. При повторе/выходе отменяются ещё не выданные записи SDK с сохранением последовательной очереди; уже отправленный запрос SDK отозвать нельзя. Кешируемая страница сохраняет ресурсы сцены и комнаты; возобновлённая попытка остаётся тренировочной и требует нового ввода.

Небольшой известный дефект: если закрыть загружаемую таблицу кнопкой «Назад», запоздавший ответ может снова открыть её; повторное нажатие возвращает результат. Устранение отложено после финального ревью.
