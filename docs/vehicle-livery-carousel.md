# Per-vehicle circular livery carousels

Each of the eleven vehicle rows contains only a transparent 3D carousel and a Select button below it. The focused model is now approximately 27% larger in screen width and height than the prior SHOP framing. Rear neighbors use a tighter, responsive orbit; the row heights and all hangar/gameplay transforms remain unchanged. The current finish appears centrally in front, with the previous and next finishes smaller and behind it. There are no card backgrounds, clickable vehicle cards, labels, captions, arrows, dots or instructional copy. The modal title and close control remain. Status and vehicle/finish names are available to screen readers only.

Horizontal dragging drives a continuous position and releases into a 260 ms eased circular transition. Both ends wrap seamlessly. Vertical gestures remain native list scrolling. Keyboard Arrow keys and Home/End work on the viewport; focus stays trapped in the modal. Reduced-motion users get immediate settling and no idle rotation. Swiping is preview-only; only explicit Select for the standard/base finish can invoke the application callback. Locked finishes remain disabled even if a DOM button is manually enabled, and the application callback separately rejects non-base finishes.

`dist/item-carousel.js` is reusable and has no vehicle, shop, currency or WebGL dependencies. It accepts items and an onSelect callback. The host controls selection with update(); a caller-provided renderer reads `viewport.carouselPosition` (continuous, allowed to exceed the item count for smooth wrapping). The component creates no slide buttons and never selects on click. Lifecycle methods cancel animations, reset pointer capture and remove listeners.

`createVehicleLiveryGallery` renders actual isolated vehicle clones with their own livery materials to one shared offscreen WebGL canvas, copying frames to visible rows' 2D canvases. Visible rows load lazily; hidden rows release their preview clones and textures and recreate them lazily when visible again. DPR is capped at 1.5 and idle rotation at 30 FPS (direct swipe motion follows animation frames). Source geometry/materials remain unchanged. Closing cancels requests, removes canvases, destroys preview materials/controllers and releases the shared GPU context. No preview is persisted or sent to multiplayer.

Verification: `npm run test:liveries`, `npm run build:all`, and a standalone development preview build with `PUBLIC_GAME_DEVELOPMENT=1`. The real-mesh size regression also samples full idle rotations and fractional wraps at mobile row heights (195–250px), 280/320/360/400px widths with panel/scrollbar insets, and 640px desktop canvases. Tests cover base-only Select, callback isolation, keyboard, vertical/horizontal/outside-release gestures, fractional interpolation, seamless wrap, async supersession, close/reopen, lazy visibility, shared GPU context and cleanup. CPU tests do not establish actual browser/GPU appearance. A local Chromium visual harness is retained under qa/carousel-orbit; this sandbox prevented Chromium from starting due to process socket restrictions.
